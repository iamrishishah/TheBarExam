Interface & data

Case names & legislation titles

Case names and legislation titles are set in Source Serif 4 italic — a genuine cursive-influenced italic, used as a narrow-purpose accent face so italics satisfy the legal citation convention properly. Stack Sans continues to handle everything else in the system, unchanged.

Seeing it in real use

A single worked passage rather than an isolated phrase — every formatting convention a legal document actually uses, applied at once, each one numbered against the table below so it's clear why that convention exists, not just that it does.

Exhibit AIllustrative practitioner's case note — Evidence

The rule in Browne v Dunn requires that if a party intends to challenge a witness's account, the challenge must be put to the witness in cross-examination, giving them a fair opportunity to respond. A related principle from Jones v Dunkel (1959) 101 CLR 298 allows a court to draw an inference unfavourable to a party who, without explanation, fails to call a witness who could reasonably have been expected to give material evidence.

Before relying on either rule, counsel should confirm:

  1. that the witness was available and capable of giving material evidence;
  2. that no satisfactory explanation has been offered for their absence; and
  3. that the inference sought is properly available on the pleadings.

Courts will also weigh less formal factors, including:

  • whether the missing evidence is merely cumulative;
  • the overall strength of the case without it; and
  • any forensic disadvantage to the opposing party.

A typical defence might respond that ‘the plaintiff’s account is unreliable and the defendant did not consider the witness’s evidence necessary’ — a submission that is unlikely to satisfy a submission the court will scrutinise closely under the amended s 21(2) of the Evidence Act 1995 (NSW).

Illustrative only — case names, section numbers and submissions are constructed for demonstration and are not verbatim citations.

Foundation

Corner radius

A small, fixed set of corner radii keeps every surface feeling like one family. Match the radius to the element's size: tighter on small controls, softer on large containers. Never mix arbitrary values.

Nesting rule. When one rounded element sits inside another, the inner radius should be smaller than the outer — roughly outer minus the padding. A --r-md input inside a --r-lg card looks right; matching radii make the inner element bulge at the corners.

Voice & tone

Our students are often stressed and short on time. Every word should be understood on the first read. Voice stays the same everywhere — clear, calm, human. Tone flexes with the moment: warm when they succeed, plain and reassuring when something breaks.

Principles

01

One read, one meaning

If a sentence needs re-reading, rewrite it. Short sentences, one idea each.

02

Lead with what matters

Put the outcome or the action first. Don't bury it after background.

03

Everyday words

Use the word people say out loud. Keep legal terms only where students expect them.

04

Say what to do next

Tell them exactly what happened and the next step. Never leave them guessing.

05

Never blame the user

Errors describe the problem and the fix, calmly. No "you did this wrong".

06

One word per thing

Pick a term and keep it. Always "enrol" — not sign up, register, or join.

Microcopy rules

Buttons are verbs

Start with an action and name the outcome: "Save answer", "Book exam". Sentence case, no full stop.

Errors = problem + fix

Say what happened, then how to fix it, in one line. Keep the tone calm.

Numbers over vague words

Positive framing

Tell people what they can do, not only what they can't. Reassure under pressure.

Iconography

Icons speed up scanning and save space — but only when they're consistent. We use Tabler Icons: an open-source (MIT) set of 5,000+ icons drawn on one grid, so everything matches out of the box. Don't mix in icons from other libraries.

Anatomy

24px grid

Every icon is drawn in a 24×24 box with consistent padding, so they optically align.

2px stroke

Outline style, 2px stroke, rounded caps and joins — it pairs with Stack Sans's clean geometry.

currentColor

Icons inherit text colour by default. Set colour on the element, not the SVG.

Tokenised colour

Colour comes from the color.icon.* tokens — never arbitrary hex.

The set

A sample — the full library lives at tabler.io/icons

Sizes

Match the icon to the text or control beside it. Use the scale — don't pick arbitrary pixel sizes.

Size scale

Stroke weight

2px is the default at 16–24px. Above ~32px, drop to 1.5px so the icon doesn't look heavier than the text around it. Never scale a 24px icon up with transform — it thickens the stroke; re-render at the target size.

Keep the optical weight even

Colour

Default icons are neutral (color.text.subtle). Colour carries meaning, not decoration: brand for brand actions, a semantic colour only to reinforce a status. One accent per group, and keep meaningful icons at 3:1 contrast — the color.icon.* tokens already pass.

Neutral by default · colour = meaning

Outline vs filled

Outline is the default. Use the filled variant to show an active or selected state — a selected nav item, a favourited row — so state reads at a glance. Don't mix the two arbitrarily.

Filled = active / selected

In context

Match the icon size to its neighbour; keep 8px between icon and label

Rules

Pair with labels

Prefer icon + text. Icon-only is fine for universal actions (search, close, menu) — always with an accessible label or tooltip.

Accessibility

Icon-only controls need an aria-label; decorative icons get aria-hidden="true" so screen readers skip them.

One weight, one grid

Don't mix Tabler with other icon sets — stroke and grid won't match.

No colour for decoration

If the colour doesn't mean something, keep the icon neutral.
Foundation

Motion

The best interfaces animate rarely, and only on purpose. Motion here earns its place by doing a job — giving feedback, showing where something came from, or guiding attention — and then getting out of the way.

Built with Motion (formerly Framer Motion). Grounded in Material's motion principles, Emil Kowalski's restraint-first thinking, and a systematised token set.

Animate, or don't

The first decision is always whether to animate at all. Frequency is the deciding factor: the more often a user sees something, the less it should move.

✓ Animate when it does a job
It gives feedback — a button press, a toggle, a saved state.
It shows where something came from or went — menus, dialogs, expanding panels.
It shows a relationship or hierarchy — a child opening from its parent.
It softens a jarring change — content loading in, a list re-ordering.
Rare, delightful moments — a first-run welcome, a "cohort passed" celebration.
✗ Don't animate when it gets in the way
The action repeats all day — a row hover, a checkbox in a long form.
It's keyboard-driven — typeahead, list navigation, shortcuts. Keep these instant.
It delays the user or blocks input while playing.
It's decorative — motion with no meaning is just noise.
It loops or pulses to grab attention — it reads as an error or an ad.

Three roles

Every animation we keep should be doing one of these jobs (Material's framing). Expressive is the rarest — reserve it for moments users meet occasionally.

Informative

Show relationships

Explain where things come from, where they go, and what's connected. Enter/exit, expand/collapse.

Focused

Direct attention

Point the eye to the one thing that changed — a new banner, an updated value — without a circus.

Expressive

Add character (sparingly)

Personality and delight for rare, memorable moments only. Never on the daily path.

Interface motion stays under ~300ms — a 180ms menu feels responsive where a 400ms one feels slow. Bigger surfaces and longer distances take the higher end.

Using it with Motion

Engineers consume the same tokens:

import { motion, useReducedMotion } from "motion/react"

const duration = { fast: 0.16, medium: 0.24, slow: 0.36 }
const ease = { standard:[.2,0,0,1], entrance:[0,0,0,1], exit:[.3,0,1,1] }

// 1 — feedback: confirm a press
<motion.button whileTap={{ scale: 0.96 }}
  transition={{ duration: duration.fast, ease: ease.standard }}>Enrol now</motion.button>

// 2 — origin-aware menu (grows from its trigger)
<motion.div style={{ transformOrigin: "top" }}
  initial={{ opacity: 0, scale: 0.96 }} animate={{ opacity: 1, scale: 1 }}
  exit={{ opacity: 0, scale: 0.96 }}
  transition={{ duration: duration.fast, ease: ease.entrance }} />

// 3 — collapse / expand (animate height)
<motion.section initial={{ height: 0, opacity: 0 }}
  animate={{ height: "auto", opacity: 1 }} exit={{ height: 0, opacity: 0 }}
  transition={{ duration: duration.medium, ease: ease.standard }} />

// 4 — respect the user
const reduce = useReducedMotion()
<motion.div animate={{ opacity: 1, y: 0 }}
  transition={{ duration: reduce ? 0 : duration.medium }} />

Reduced motion

Always honour it. When a user asks for less motion, movement collapses to a simple fade and loops stop. Use Motion's useReducedMotion(), or gate transforms behind @media (prefers-reduced-motion: reduce). Every demo on this page already respects it.
